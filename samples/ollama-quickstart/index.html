Sample · Documentation rewrite

Ollama API — a quickstart that actually reaches a working call

The official docs/api.md is a complete reference and not a quickstart. This rewrite takes a developer from a fresh install to a verified first call in five minutes, and covers the two failure modes the reference does not mention at all.

Project Ollama Tested against 0.40.13 Platform Windows 11 Date 2026-11-04

What was wrong with the existing docs

Five defects. Every one was verified by making the call myself, not by reading the page and forming an opinion.

01

No install or server-start step

ollama serve appears nowhere in the API doc. A reader whose server is not running gets connection refused and no guidance.

02

Silent about authentication

Every example omits an auth header. The docs never state that auth does not exist, so readers go looking for an API key that was never issued.

03

Examples assume a model you do not have

All examples use llama3.2. First call on a fresh install returns HTTP 404 {"error":"model 'llama3.2' not found"} — reproduced.

04

thinking is in every response and documented nowhere

Reasoning models return a thinking string absent from every documented response schema. A reader printing response gets an empty string and concludes the API is broken.

05

The streaming wire format is never shown

Docs say responses “stream as JSON objects” but never show that the body is newline-delimited JSON — not an array, not SSE. json.loads() on the full body raises.

The rewrite

1 — Install, and confirm the server is running

ollama --version
ollama serve

curl http://localhost:11434/api/version
# {"version":"0.40.13"}

If that returns nothing, the server is down and nothing below will work. One check eliminates roughly half of all “the API doesn't work” reports.

2 — There is no authentication

Ollama binds to 127.0.0.1:11434 with no key, no bearer token, no auth header. The examples omit one because there isn't one.

The consequence worth stating: anything on your machine can call your models. Setting OLLAMA_HOST=0.0.0.0 publishes an unauthenticated API to your network.

3 — Pull the model you will actually call

ollama pull qwen3.5:4b
curl http://localhost:11434/api/tags

Use the exact models[].name value from that response. A name not in the list is the single most common first-call failure.

4 — First call

curl http://localhost:11434/api/generate -d '{
  "model": "qwen3.5:4b",
  "prompt": "Reply with exactly: OK",
  "stream": false
}'

Real response, trimmed:

{
  "model": "qwen3.5:4b",
  "response": "OK",
  "thinking": "Thinking Process:\n\n1. ...",
  "done": true,
  "done_reason": "stop",
  "eval_count": 206,
  "eval_duration": 39693751000
}

5 — The reasoning-model trap

Empty response, populated thinking, and done_reason: "length" means the model spent its whole token budget reasoning. It is not broken — raise num_predict, or pass "think": false. 

{"response": "", "thinking": "Thinking Process:\n\n1.  **",
 "done_reason": "length"}

6 — The streaming format

Streaming is on unless disabled, and the body is newline-delimited JSON. Parse line by line; stop at the object where done is true. 

{"model":"qwen3.5:4b","response":"OK","thinking":"Thinking","done":false}
{"model":"qwen3.5:4b","response":"","done":true,"done_reason":"stop"}

7 — A tested client, standard library only

The reference shows curl only. This is the equivalent in the standard library, with both modes. The code below was extracted from this page and executed before publishing. 

import json
import urllib.error
import urllib.request

BASE = "http://localhost:11434"


def _post(path, payload, timeout=300):
    req = urllib.request.Request(
        BASE + path,
        data=json.dumps(payload).encode(),
        headers={"Content-Type": "application/json"},
    )
    try:
        return urllib.request.urlopen(req, timeout=timeout)
    except urllib.error.HTTPError as e:
        raise RuntimeError(f"Ollama error {e.code}: {e.read().decode()}") from e


def generate(prompt, model="qwen3.5:4b", num_predict=256):
    """One call, one answer. Raises if the model only 'thought'."""
    resp = _post("/api/generate", {
        "model": model,
        "prompt": prompt,
        "stream": False,
        "options": {"num_predict": num_predict},
    })
    data = json.loads(resp.read())
    if not data.get("response") and data.get("thinking"):
        raise RuntimeError(
            f"Model reasoned but produced no answer "
            f"(done_reason={data.get('done_reason')}). Raise num_predict."
        )
    return data["response"]


def generate_stream(prompt, model="qwen3.5:4b", num_predict=256):
    """Yields text chunks. Responses are NEWLINE-DELIMITED JSON."""
    resp = _post("/api/generate", {
        "model": model,
        "prompt": prompt,
        "stream": True,
        "options": {"num_predict": num_predict},
    })
    for line in resp:
        line = line.strip()
        if not line:
            continue
        chunk = json.loads(line)
        if chunk.get("done"):
            break
        if chunk.get("response"):
            yield chunk["response"]

Two functions rather than one with a stream flag, because a single function containing yield always returns a generator — a bug I hit in my own first draft, which returned a generator even when stream=False.

9 — Checkpoint

  • /api/version returns a version
  • /api/tags lists your model
  • A stream:false call returns text in response
  • You know there is no auth and the port must not be exposed

How this was written

I start from the running system, not the document. Every number on this page — the 404 body, the thinking field, the chunk format, the 5.2 tokens/sec — came from calling a live server on the machine below. Where I could not test something, I say so: all verification was on Windows 11, and macOS and Linux were not tested.

If your documentation is written from an outline rather than from a running install, the failure modes above are what your readers are hitting and reporting as bugs.
