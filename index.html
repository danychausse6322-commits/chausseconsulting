About

Five years of engineering, then the automation layer on top.

I'm Dany Chausse. I spent five years building and maintaining technical systems where you find out whether the work was correct by testing it, not by looking at it.

That work trains one specific habit: you don't call a system working because it looks right. You test it, you record the result, and you put your name on it. It's also why I care about the boring half of automation — the runbook, the failure path, the handover document nobody reads until the day they desperately need it.

In practice: I build local AI agent stacks on models I run myself, so a client's data never has to leave the building to get the benefit. And I write technical documentation that ships with the code it describes and the terminal output it actually captured.
